# راهنمای طراحی و نگهداری

این راهنما اجزای طراحی و گردش کارهای قابل استفاده برای وب‌سایت «روان‌کاوی با سینا» را ثبت می‌کند. ساختار Astro، خروجی استاتیک، مسیر مقاله‌ها، Content Collection و پیکربندی Cloudflare حفظ شده‌اند.

## سیستم طراحی

توکن‌های رنگ، تایپوگرافی، فاصله‌گذاری، عرض محتوا، گوشه‌ها و فوکوس در `src/styles/global.css` تعریف شده‌اند. سفید رنگ غالب است و ذغالی، فیروزه‌ای و یاقوتی برای سلسله‌مراتب و تأکیدهای محدود به کار می‌روند. طرح‌بندی‌ها از فضای خالی، تایپوگرافی فارسی و تصویرهای اختصاصی موجود استفاده می‌کنند.

- عرض متن مقاله با توکن `--reading-width` محدود می‌شود.
- متن رابط و مقاله از فونت محلی Estedad استفاده می‌کند؛ Markazi Text برای کاربردهای ادبی و نقل‌قول‌ها در دسترس است.
- وزن‌های متغیر فونت با `font-display: swap` بارگذاری می‌شوند. فایل‌های فونت و مجوز OFL آن‌ها در `public/fonts/` نگهداری شده‌اند.
- برای احترام به تنظیمات سیستم، حرکت‌های غیرضروری با `prefers-reduced-motion` کاهش می‌یابند.
- برای تغییر ظاهر سراسری، ابتدا توکن‌های CSS را ویرایش کنید و از افزودن رنگ یا اندازهٔ موردی به هر صفحه بپرهیزید.

## آیکون‌ها

آیکون‌های رابط از `@lucide/astro` می‌آیند و به‌صورت SVG در خروجی Astro رندر می‌شوند؛ نیازی به بارگذاری کتابخانهٔ جاوااسکریپت یا سرویس خارجی نیست:

```astro
---
import { ArrowLeft } from '@lucide/astro';
---

<ArrowLeft size={18} stroke-width={1.7} aria-hidden="true" />
```

آیکون تزئینی باید از فناوری‌های کمکی پنهان باشد؛ اگر آیکون تنها محتوای یک کنترل است، خود کنترل باید نام قابل‌دسترسی داشته باشد.

## تصویرها و SVG

- تصویرهای مقاله در `public/images/articles/` و تصویرهای صفحهٔ اصلی در `public/images/hero/` نگهداری می‌شوند.
- مسیر تصویر در فرانت‌متر مقاله باید با مسیر عمومی آن، مانند `/images/articles/example.svg`، مطابقت داشته باشد.
- متن جایگزین باید محتوای واقعی یا کارکرد تصویر را توصیف کند؛ برای تصویر تزئینی از متن جایگزین خالی استفاده شود.
- برای تصویرهایی که در طرح‌بندی فضای مشخص دارند، ابعاد `width` و `height` را نگه دارید تا از جابه‌جایی ناخواستهٔ محتوا جلوگیری شود.
- SVGهای موجود با نسخهٔ نصب‌شدهٔ SVGO بهینه شده‌اند. برای فایل جدید می‌توان همان ابزار محلی را به‌کار برد: `npx svgo public/images/example.svg --multipass`. پیش از ثبت، نمایش خروجی را بررسی کنید.
- تصویر JPG موجود در `public/uploads/` استفاده‌ای در صفحات یا مقاله‌های فعلی ندارد؛ حفظ شده و تبدیل یا حذف نشده است.

## فونت‌ها

فونت‌ها از منابع رسمی دریافت و در پروژه میزبانی می‌شوند تا رندر سایت به CDN فونت وابسته نباشد. فایل‌های OFL همراه فایل‌های WOFF2 در `public/fonts/` قرار دارند. پیش از افزودن وزن یا فونت تازه، بررسی کنید که نیاز بصری آن با خانواده‌ها و وزن‌های موجود برطرف نمی‌شود؛ فایل مجوز فونت نیز باید همراه آن ثبت شود.

## اعتبارسنجی، تست و ساخت

`npm run validate` فرمان یکپارچهٔ اعتبارسنجی است. آن را پس از تغییرات رابط یا کد اجرا کنید. این فرمان به‌ترتیب بررسی Astro/TypeScript، ESLint، Prettier، آزمون‌های واحد، آزمون‌های مرورگر Playwright و ساخت را اجرا می‌کند. خروجی Playwright و گزارش‌های تولیدشده فایل‌های موقت‌اند و در Git ثبت نمی‌شوند.

فرمان‌های جداگانه:

```sh
npm run check
npm run lint
npm run format:check
npm run test
npm run test:e2e
npm run build
```

تست مرورگر به مرورگرهای نصب‌شدهٔ Playwright نیاز دارد. تست دسترس‌پذیری از `@axe-core/playwright` استفاده می‌کند. اگر محیط مرورگر یا Lighthouse در دسترس نباشد، نتیجهٔ آن را ناموفق یا تأییدشده گزارش نکنید؛ محدودیت را جداگانه ثبت کنید.

`npm run build` خروجی ایستا را در `dist/` تولید می‌کند. گردش‌کار [Validate site](../.github/workflows/validate.yml) بررسی‌ها، تست‌ها و ساخت را روی Pull Requestهای مقصد `main` و هر push به `main` اجرا می‌کند؛ انتشار خودکار را انجام نمی‌دهد. انتشار به Git integration موجود Cloudflare واگذار شده تا دو سامانه هم‌زمان deploy نکنند. تنظیمات Wrangler، مسیر دارایی‌های `dist` و رفتار صفحهٔ 404 دست‌نخورده مانده‌اند. برای انتشار دستی، اپراتور مجاز می‌تواند پس از ساخت و بررسی خروجی `npx wrangler deploy` را اجرا کند.

## سئو و انتشار

Layout عنوان، توضیحات، زبان فارسی، Open Graph و Twitter Card را فراهم می‌کند. Canonical و URLهای کامل اجتماعی فقط وقتی ساخته می‌شوند که `site` در پیکربندی Astro به نشانی عمومیِ تأییدشده تنظیم شده باشد. این مخزن نشانی عمومی تأییدشده‌ای در پیکربندی در دسترس ندارد؛ بنابراین نشانی حدس زده نشده است. در نتیجه sitemap و دادهٔ ساختاریافته‌ای که به URL یا مشخصات نویسندهٔ تأییدنشده متکی باشد، عمداً اضافه نشده‌اند. `public/robots.txt` برای خزش آزاد است؛ پیش از انتشار عمومی، URL رسمی را تعیین و نیاز به sitemap را دوباره بررسی کنید.

## ابزارها و دامنهٔ تغییر

در این کار وابستگی تازه‌ای نصب نشده است. ابزارهای موجود پروژه برای Astro Check، ESLint، Prettier، Vitest، Playwright، axe-core، Lighthouse، SVGO، Sharp و Wrangler بررسی شدند. آزمون‌های واحد و مرورگر در اعتبارسنجی خودکار هستند؛ Lighthouse ارزیابی دستی/محلی مکمل است و به Chromium نیاز دارد. Sharp در این تغییر برای تولید تصویر مشتق‌شده استفاده نشده، چون تنها فایل Raster شناسایی‌شده استفاده‌ای ندارد و کوچک است.

هیچ GitHub Actions یا گردش‌کار انتشار تازه‌ای اضافه نشده است. تنظیم Wrangler، مقالات Markdown، URLهای موجود و محتوای آن‌ها عمداً تغییر نکرده‌اند. اقدامات کیفی مانند بررسی اعتبار علمی، صحت ارجاعات، مناسبت متن جایگزین و بازبینی بصری همچنان به بازبینی انسانی نیاز دارند.
